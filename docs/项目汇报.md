# TMS 运输管理系统 · 项目汇报

> 版本：v1.0（2026-09）　技术栈：JDK 8 · Spring Boot 2.7 · MyBatis-Plus · Vue 3 · Element Plus
> 仓库：<https://github.com/mengzhihua/tms>

---

## 1. 项目背景与目标

| 维度 | 内容 |
| --- | --- |
| 背景 | 物流运输环节缺乏统一系统，订单、调度、在途、结算分散在表格与聊天工具中，难以对时效和成本进行管控 |
| 目标 | 建设一套**行业标准 TMS**，对标富勒（Flux）与科捷金库 TMS 公开能力，覆盖"订单 → 筛单 → 调度 → 装车 → 在途 → 签收 → 回单 → 结算 → 评级"全链路 |
| 范围 | 自建车队 + 三方快递/物流双模式；电子围栏；体积测算；开放接口对接 WMS/OMS |
| 约束 | JDK 8 运行环境；前后端分离；默认零依赖启动（内嵌 H2），可切换 MySQL |

## 2. 建设成果概览

| 层次 | 技术选型 | 说明 |
| --- | --- | --- |

## 5. 核心业务流程

```mermaid
sequenceDiagram
    participant C as 客户/WMS
    participant T as TMS
    participant S as 智能筛单
    participant V as 自建车辆/司机
    participant P as 三方承运商
    C->>T: 创建订单（明细含长宽高/重量）
    T->>T: 体积 = Σ 长×宽×高×件数，抛重 = 体积/抛比，计费重 = max(实重, 抛重)
    T->>S: 筛单（区域覆盖 → 时效 → 按策略排序）
    S-->>T: 推荐承运商 + 预估运费 + 承诺时效
    alt 自建物流
        T->>V: 调度配载（载重/容积校验）→ 装车单 → 发车
        V->>T: GPS 上报
        T->>T: 围栏进出判定 → 告警；SLA 扫描 → 超时异常
        V->>T: 到达 → 签收（POD）
    else 三方物流
        T->>P: 适配器下单
        P-->>T: 轨迹同步 / 状态回调
    end
    T->>T: 生成计费单 → 支付
    T->>T: 回单归档 → 承运商月度评级
    T-->>C: 路由/状态回传
```

## 6. 关键技术点

| 主题 | 方案 |
| --- | --- |
| 计费重 | `chargeableWeight = max(Σ weightKg, Σ (L×W×H×qty)/divisor)`，抛比默认 6000，可按承运商配置 |
| 电子围栏 | 圆形：Haversine 距离 ≤ 半径；多边形：射线法；上一点在内、当前在外触发 EXIT，反之 ENTER |
| 智能筛单 | 覆盖过滤 → 时效过滤 → 用区域价格试算每个候选的运费与承诺时效 → 按策略（COST / TIME / DESIGNATED）排序取首位；无候选时返回原因 |
| 超时扫描 | 发车超计划 30 分钟 / 在途超承诺到达 / 到达 24h 未签收，三类分别登记；同运单同类型未关闭则不重复 |
| 承运商评级 | `score = 准时率×50 + (1-异常率)×30 + 回单率×20`，≥90 A / ≥75 B / ≥60 C / 其余 D |
| 三方对接 | `ThirdPartyLogisticsAdapter` 接口（createShipment / queryTrack / cancel），Mock 实现模拟揽收→在途→签收；`/api/thirdparty/callback/{provider}` 接收状态回调并写入轨迹 |
| 编码一致性 | `sql.init.encoding=UTF-8`、HTTP 强制 UTF-8、`-Dfile.encoding=UTF-8`，杜绝 Windows/GBK 乱码 |
| 空值语义 | 前端清空下拉发送空串，后端统一 `isNotBlank` 判定；订单修改用 `LambdaUpdateWrapper.set` 显式清空可选字段 |

## 9. 现状评估与后续规划

**已具备**：完整的 TMS 主流程、双模式运力、围栏与超时预警、异常理赔、结算评级、开放接口，可作为演示与 PoC 直接使用。

**当前限制**：
- 三方承运商为 Mock 适配器，未接真实快递 API；
- 无登录/权限体系（当前固定 admin）；
- 默认 H2 文件库，未做生产级数据库与监控；
- 一辆车同时仅支持一张在途运单（调度校验车辆空闲）。

**后续规划**：

| 阶段 | 内容 |
| --- | --- |
| 近期 | 接入真实快递电子面单 API（顺丰/京东/中通）；Spring Security + JWT 登录与角色权限；MySQL 生产配置与 Flyway 迁移 |
| 中期 | 司机端 H5/小程序（接单、GPS 上报、拍照签收）；路径规划与多点配送排线；运费对账与承运商结算单 |
| 远期 | 与 WMS/OMS 深度集成（出库 → 自动建单 → 回传）；运营看板与告警推送（钉钉/企微）；多租户与 SaaS 化 |
